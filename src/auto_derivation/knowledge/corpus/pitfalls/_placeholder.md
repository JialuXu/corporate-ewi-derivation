# pitfalls/ — 五类陷阱案例库（见 DESIGN.md §8）

每个坑一个 markdown，记录业务案例。
meta_report 的"五类陷阱自检"会引用这里。

**提交到本仓库的案例必须完全脱敏**：不得出现真实客户、机构、人员、地区或可反推身份的金额与日期。

文件名建议格式：

- `坑1-PSI单一稳定性误判.md` — 小样本 PSI 在 KL 散度看时是漂移
- `坑2-征信无查询vs查询失败.md` — null_semantics 区分丢失导致的真实事故
- `坑3-同期特征污染.md` — 没做 3-月 lag 的伪强指标
- `坑4-跨行业混搜.md` — 制造-批零混搜产生的不可解释规则
- `坑5-LLM解释幻觉.md` — 业务字段对、统计漂亮但因果讲不通的案例

每篇结构建议：

```
## 案例背景
[匿名客户、行业、时点]

## 错误发生的链路
[GP 找到什么 → LLM 怎么解释 → 上线后什么后果]

## 后验的根因
[数据契约问题 / 类型系统漏洞 / 知识库缺失 / 等等]

## 此后应增加的校验
[machine check / suspicion 规则 / 监控指标]
```

文件名以 `_` 开头会被 loader 跳过（本文件即占位）。
